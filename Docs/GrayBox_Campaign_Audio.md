# Campaign audio in SB_GrayBox

Only audio tracks were added to the ten existing opening, interlude, L01 and L02 sequences. Their non-audio exported object data, bindings, camera cuts, animation, transform, fade, frame rate and playback ranges compare identically. Existing camera startup audio is retained. Neither map nor campaign source assets were saved or changed.

`Tools/Cinematics/InstallCampaignAudio.py` installs the named `Campaign VO (audio only)` track idempotently, using whole-phrase offsets from the campaign narrative manifest. Original sounds are referenced directly. Opening audio follows existing subtitle starts at 2/7/11/17 seconds; interlude follows 0/3.44/7.95/10.68/15.19. L01/L02 perfect recordings are split across their opening and outcome sequences. Failure sequences use Maya's complete response; Surya's following hint is omitted. Intro, transitions and later campaign-only sequences have no matching target and are omitted. See `Saved/GrayBoxAudio/installation.json` for the full placement/omission list. Subtitle logic is preserved; failure captions still use their existing post-outcome timing, so perfect caption/audio synchronization is not claimed there.

`Tools/Cinematics/PatchCutAudio.py` extends the existing Film Scene Manager. `ResetTake` already calls `SequencePlayer.Stop`, which stops Sequencer audio. ManualCut now plays the derived 0.55-second CUT shout immediately after ResetTake. The clip contains only ?CUT!? before the following sentence. One auto-destroying AudioComponent is owned by the manager; StopDialogue/reset/new take and EndPlay stop it. Existing ACTION/CUT eligibility is retained: a subsequent press in SETUP may start a retake, which clears the previous shout. Ambience and unrelated sound components are not stopped.

## Runtime evidence

All behavior tests ran in PIE in a separate hidden process with `-RenderOffscreen -NullRHI -DeterministicAudio -UseFixedTimeStep -FPS=60 -unattended -nosplash -nop4 -MCPBridgePort=8775`. A process-local `-ini:Engine:[Audio]:UnfocusedVolumeMultiplier=1.0` allows internal recording; the NonRealtime renderer uses no physical audio device. The process was launched Hidden at BelowNormal priority, without OS mouse/keyboard injection, foreground activation or computer-use tools. No Edit Mode unit tests were run.

`Tools/Cinematics/VerifyGrayBoxAudioRuntime.py` runs the production manager and sequences in SB_GrayBox PIE. Fifty assertions passed across all ten sequence playbacks, sequence completion, CUT during three active dialogue examples, repeated action/new take cleanup, opening stop/skip, reset and EndPlay. The final interlude timing revision received eight additional PIE checks. A late CUT at 4.2 seconds during the five-second blocked sequence received 14 further runtime checks. Live voice-component checks are complemented by non-silent PCM captures. Whole-phrase waveform correlation is diagnostic rather than an acceptance gate because compressed/rendered audio block alignment and fades differ from raw WAV sources. The recordings were not manually auditioned through speakers.

Evidence: `Saved/GrayBoxAudio/Runtime/report.json`, `RuntimeInterlude/report.json`, `RuntimeLateCut/report.json`, `pcm_verification.json`, `summary.json` and WAV captures. Compilation: zero errors and warnings. Source hashes confirm SB_GrayBox.umap and all IbraCampaign files are unchanged. Binary backups and before/after sequence exports are under `Saved/GrayBoxAudio/Backup` and the parent folder.
